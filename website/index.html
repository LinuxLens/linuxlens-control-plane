Open source

Run LinuxLens on your server.

Install the CLI, collect facts, and get a deterministic risk assessment. Nothing is uploaded. No packages, kernels, or services are changed.

1. Install

curl -fsSL https://linuxlens.suherman.net/install.sh | bash
source ~/.linuxlens_env

Or clone the GitHub repository and install the CLI from ./cli.

2. Assess this host

linuxlens assess localhost

Collects inventory and prints lifecycle, patch posture, LinuxLens risk (0–100), and capability-first remediation options.

3. Offline / regulated

linuxlens collect --archive ./linuxlens-assessment.tar.gz
# copy the archive out, then:
linuxlens assess --from-archive ./linuxlens-assessment.tar.gz

Use when hosts must not reach the Internet. The archive contains structured evidence only.

Never collected

  • Passwords and private keys
  • API tokens and secrets
  • Database contents and documents
  • User home-directory data

Many servers

# on each host (Ansible / SSH)
linuxlens collect --archive host-$(hostname).tar.gz

# on your workstation
linuxlens assess --from-archive ./host-prod-db-01.tar.gz \
  --criticality critical \
  --maintenance-window quarterly \
  --workload postgresql

How it works

Facts in. Decisions out. No silent vendor default.

  1. 01

    Collect

    A read-only collector gathers host, OS, kernel, package, update, and operational metadata. Passwords, keys, and customer data stay out.

  2. 02

    Assess

    A deterministic engine scores lifecycle, patch lag, exposure, and operational constraint against published rules — not an LLM judgement.

  3. 03

    Recommend capability

    Patch, live patch, upgrade, migrate, extended support, compensate, or accept risk. The capability comes first.

  4. 04

    Map providers

    Only then: compatible products. “Live kernel patching is recommended.” Then, optionally, who can fulfil it.

Connected

Hosts → collector → HTTPS → LinuxLens API. Best for SaaS estates.

Offline

Collector writes linuxlens-assessment.tar.gz. Manual import. Nothing needs outbound Internet.

Relay

Hundreds or thousands of servers. Only the relay needs outbound connectivity.

Primary recommendation

Apply non-disruptive mitigation immediately, then schedule operating system migration as the long-term remediation.

  • Live patch — low impact, no downtime, immediate risk reduction
  • Extended support — runway while migration is planned
  • Migrate / upgrade — durable fix, downtime required

Compatible providers are listed after the capability — never instead of it.

Principles

Independence is the product.

Vendor-neutral

TuxCare, Canonical, Red Hat, and SUSE can fulfil a capability. None of them own the score.

Capability-first

We never lead with “buy KernelCare.” We lead with live kernel patching, then who can deliver it.

Read-only

The collector does not patch, enrol, or change services. Safe to run on production hosts.

Deterministic

AI may explain a Critical host. It does not decide the host is Critical. Every answer traces to evidence.
